# 2026-10-02

## 修复：翻译配置页「翻译模型」行无法点击

### 现象
用户报告 `Views/Sections/TranslationSection.xaml` 中「翻译模型」下拉框、「刷新模型」按钮、「测试翻译」按钮全部无法点击；页面其它控件（开关、端点输入框、目标语言下拉框、提示词文本框等）正常。

### 根因（已确认）
外层 Grid（27-74 行）的 `Grid.RowDefinitions` 只声明了 2 个 RowDefinition（索引 0、1），但第 70 行的 `OllamaStatusTextBlock` 写了 `Grid.Row="2" Grid.ColumnSpan="2"`。

WinUI 3（与 WPF 行为一致）的规则：`Grid.Row` 索引超出 `RowDefinitions.Count - 1` 时**不会**自动插入新行，而是被**强制塞回最后一行**。所以这个 TextBlock 实际落到 Row 1 上，加上 `ColumnSpan="2"`，覆盖整个 Row 1。TextBlock 即便 `Text=""` 也会占据布局矩形并吞掉命中测试。Row 0 元素未被覆盖故能点击 —— 与用户观察一致。

### 修复（已实施）
文件：`Views/Sections/TranslationSection.xaml`，2 处微改：

1. 第 32-35 行 `Grid.RowDefinitions` 补第 3 个 `<RowDefinition Height="Auto" />`，让 Row 2 真正存在。
2. 第 70 行 `OllamaStatusTextBlock` 加 `IsHitTestVisible="False"`（防御性加固）：状态文本不需要接收点击；未来若 RowDefinition 再次声明错误，也不会再产生"透明拦截"类故障。

构建：0 error（20 个与本次修复无关的 `WasapiOut` 弃用警告）。

### 经验沉淀（已写入 MEMORY.md）
- WinUI 3 Grid 越界行为：参考 `Microsoft.UI.Xaml.Controls.Grid` 文档 —— `RowSpan/ColumnSpan` 大于总数会被"当成总数并跨越全部"；但 `Grid.Row/Grid.Column` 索引越界时不会自动插入新行，会被塞回最后一行 / 最后一列。
- XAML 校验规则（PR review 清单）：修改 Grid 时确认 `RowDefinition.Count > max(Grid.Row)` 且 `ColumnDefinition.Count > max(Grid.Column)`。
- 教训："元素能看见但点不到"是 WinUI / WPF 的典型症状 —— 优先怀疑 Z 序、命中测试、Grid 越界三件事；不要先入为主去查事件订阅。
