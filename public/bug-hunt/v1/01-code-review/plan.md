# 缺陷排查与修复计划

## 版本与阶段

- 功能模块：全项目缺陷排查（第一轮）
- 版本：v1
- 阶段：01 静态审查与高确定性修复
- 状态：十轮已完成（85 处修复；仍有下一轮候选，见 `result.md`）

## 目标

1. 逐模块审查设置、OSC、语音识别、实时字幕、翻译、TTS、模板与 UI。
2. 只修复有代码证据、可自洽推理的真实缺陷；不做风格性重写。
3. 每轮以 `dotnet build` 0 错误作为最低验证门槛，并记录无法在本机运行验证的限制。
4. 把已确认问题、修复位置、剩余候选写入 `result.md`，供后续轮次继续。

## 执行步骤

1. 建立基线构建，确认初始错误/警告数量。
2. 静态审查核心服务与窗口/页面代码，记录候选问题。
3. 修复高确定性缺陷，保持改动最小、可回滚。
4. 重新构建并检查 `git diff --check`。
5. 更新本计划与 `result.md`，列出仍需验证/修复的问题。

## 约束

- 保留工作区已有的 UI 优化与 TTS 流式参数修改。
- 不结束正在运行的用户程序，不修改用户配置内容。
- 运行验证仅限编译；不自动启动会连接 VRChat/Ollama/IndexTTS 的完整应用。
